1 เป้าหมาย และ ระบบทำงานอย่างไร

เป้าหมาย: รันระบบค้างไว้บนเครื่องที่รับ traffic จาก switch (SPAN) แล้วเมื่อมีสิ่งผิดปกติ เช่น ping หรือ nmap ต้องขึ้น ALERT สีแดง ภายในไม่กี่วินาที และบันทึกลงฐานข้อมูล โดยเขียนเองทั้งหมด ไม่ใช้ IDS สำเร็จรูป (Snort, Suricata, Zeek)

หลักคิด (Anomaly-based): โมเดลเรียนรู้แค่ว่า traffic ปกติ หน้าตาเป็นอย่างไร อะไรที่ต่างจากนั้นมากจะถูกมองว่า "แปลก" ไม่ต้องมีตัวอย่างการโจมตีตอนเทรน

captureดัก packet
(Wi-Fi / LAN / loopback)
➜packets
featureแปลงเป็นตัวเลข
23 ค่า / packet
➜features
detectionโมเดลให้คะแนน
score ≥ threshold = แปลก
➜detections
alertALERT สีแดง + SQLite
monitorpacket ไหลสด (ปกติเทา / แปลกแดง)

แต่ละกล่อง = โปรแกรมแยกกัน (microservice) คุยกันผ่าน ZeroMQ ด้วย JSON · ตั้งค่าทั้งหมดในไฟล์เดียว config/config.yaml

โมเดลดูอะไรใน packet (feature)

ต่อ packetprotocol (TCP/UDP/ICMP), ขนาด, TTL, TCP flags (SYN/ACK/FIN/…), ICMP type, กลุ่มของ port ปลายทาง
บริบท 5 วินาทีล่าสุด
ของเครื่องต้นทาง		ส่งกี่ packet · ไปกี่ port · ไปกี่เครื่อง · ไปกี่ port ของ service (< 49152) · สัดส่วนเครื่องปลายทางต่อ packet
→ ทำให้จับการสแกน (nmap) ได้ เพราะตัวสแกนยิงหลาย port/หลายเครื่องในเวลาสั้น

3 วิธีใช้งาน

① ติดตั้ง (ครั้งแรกครั้งเดียว)

pip install -r requirements.txt

Windows: ลง Npcap และติ๊ก Support loopback traffic · Linux: ลง libpcap

② เลือก interface ที่จะดัก

python system/scripts/list_interfaces.py

ใส่ชื่อใน config.yaml → capture.interfaces เช่น "Wi-Fi", "loopback"
ใช้ SPAN: เสียบสาย LAN เข้าพอร์ตที่ mirror แล้วใส่ "Ethernet"

③ รันระบบ (PowerShell แบบ Administrator)

cd C:\Project_AI\home-nids
python run_all.py

หน้าต่างนี้แสดง ALERT · หน้าต่าง monitor เปิดแยกเอง · ปิดด้วย Ctrl+C

④ ทดสอบ (เปิด terminal อีกอัน)

ping 172.20.10.2       # IP เครื่อง (ดู ipconfig)
nmap -sS 172.20.10.2   # ใช้ IP จริง ไม่ใช่ 127.0.0.1

ผลที่ควรเห็น:

 ALERT  12:34:56  172.20.10.2 → 172.20.10.2  ICMP
   เหตุผล: ICMP echo request (ping) ไม่พบใน traffic ปกติ  score=0.717

⑤ ดูประวัติ alert

python -c "import sqlite3; [print(r) for r in sqlite3.connect('data/alerts.db').execute('select src_ip,dst_ip,proto,count,reason from alerts')]"

⑥ ตรวจว่าโค้ดยังทำงานถูก

python -m pytest

4 ข้อควรระวัง และปัญหาที่พบบ่อย

อาการแก้ไข
ไม่พบไฟล์โมเดลรัน generate_data.py แล้ว train.py
ไม่พบ interfaceดูชื่อจาก system/scripts/list_interfaces.py
ping ตัวเองไม่ขึ้นต้องมี "loopback" ใน config + Npcap loopback
ดัก packet ไม่ได้เปิด terminal แบบ Administrator / ใช้ sudo
feature ไม่ตรงกับโมเดลแก้ features.py แล้วต้องเทรนใหม่
  • รองรับเฉพาะ IPv4
  • การสแกนที่ช้ามาก (nmap -T0/-T1) หลุดได้ เพราะดูทีละ 5 วินาที
  • ยังไม่ได้ทดสอบกับ nmap ตัวจริง, ping จากเครื่องอื่น และ SPAN จริง
  • เครื่องนี้ ห้ามใช้ pandas (Windows บล็อก) โปรเจกต์จึงใช้ numpy + csv แทน
  • TCP ระหว่าง 127.0.0.1 ↔ 127.0.0.1 ถูกข้ามโดยตั้งใจ (เป็น traffic ภายในของระบบเอง)

5 การเทรนโมเดลด้วย Jupyter (ใช้ dataset จากออนไลน์ / Wireshark)

หลักสำคัญ: เทรนด้วย traffic ปกติล้วน (ไม่ต้องมี label) — ส่วนข้อมูลที่ มีการโจมตี + label ใช้แค่ วัดผล (TP/FP/TN/FN) ถ้ามีการโจมตีปนในข้อมูลเทรน โมเดลจะเรียนว่าการโจมตีนั้นปกติ

ขั้นตอน (ทำครั้งเดียวจบใน notebook)

① โหลด datasetเลือกชุดที่มี .pcap เช่น CIC-IDS2017
② วางไฟล์ปกติ → training/pcap/normal/
มีการโจมตี → training/pcap/test/
③ เขียน labelใส่ IP ผู้โจมตี + ช่วงเวลาใน training/pcap/labels.csv
④ เปิด notebookpython -m notebook training/train.ipynb
แล้วกด Run All
⑤ อ่านผลConfusion Matrix + Accuracy, Precision, Recall, F1
⑥ ใช้งานโมเดลถูกบันทึกลง system/models/ แล้ว → รัน run_all.py ใหม่

สิ่งที่ notebook ทำให้อัตโนมัติ

ขั้นทำอะไร
0อ่าน parameter จาก config.yaml + ใช้โค้ดของ microservice (สูตร feature ตัวเดียวกับระบบจริง)
1แปลง pcap → CSV (เก็บไว้ที่ data/pcap_csv/ ครั้งต่อไปไม่ต้องแปลงซ้ำ)
2–4รวมข้อมูลปกติ ตัด ping ออก ดูกราฟ แล้วเทรน
5สร้างชุดทดสอบ: ไฟล์ใน test/ + การโจมตีจำลอง (ping, nmap)
6–7เลือก threshold แล้ววัดผล พร้อมกราฟ Confusion Matrix / ROC
8บันทึกโมเดล + threshold ลง system/models/

ตัวอย่าง: CIC-IDS2017

ไฟล์วางที่
Monday-WorkingHours.pcapnormal/ (วันปกติ)
Friday-WorkingHours.pcaptest/ (มี PortScan)

labels.csv (เอา # หน้าบรรทัดตัวอย่างออก):

PortScan,172.16.0.1,192.168.10.50,2017-07-07T13:55:00-03:00,2017-07-07T14:35:00-03:00,0,CIC Friday

ตรวจ IP/เวลากับหน้าเว็บ dataset อีกครั้ง · ไฟล์ใหญ่มาก อ่านแค่ max_packets_per_pcap (2 ล้าน) ต่อไฟล์

อ่านผลการวัด

ค่าความหมาย
TP / FNการโจมตีที่ จับได้ / หลุด
FP / TNปกติแต่ alert หลอก / ปกติและตอบถูก
Accuracyตอบถูกกี่ % (⚠️ หลอกตาเมื่อข้อมูลปกติเยอะมาก)
Precisionalert ที่ขึ้น เป็นการโจมตีจริงกี่ %
Recallการโจมตีทั้งหมด จับได้กี่ %
F1ค่าเฉลี่ยของ Precision กับ Recall
FPRtraffic ปกติ ถูก alert หลอกกี่ %
ROC-AUCแยกปกติ/โจมตีได้ดีแค่ไหน (1.0 = สมบูรณ์)
